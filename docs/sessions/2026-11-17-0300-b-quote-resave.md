## Decisions and why
Planned decisions, each the safest option found. D13 and D14 came from the critique of the first plan. Decisions taken while building go under "Decisions taken during the build".

- **D1, the server, not the client (PR #46 Q6).** A client-only fix is impossible: the answer's text fails the format (400) and typed text fails the waste check (403). It would also need every client and screen (quote builder, contract form, split dialog) to know each column's scale. The API takes back what it answers.
- **D2, spellings, not values.** The places past each rule's precision may only be zeros, up to the column's 8. Rejected: "any 8 decimals" (widens the accepted values without an owner decision) and normalising inside the schema (`transform`): numeric stores the value either way, so it buys nothing.
- **D3, answers unchanged.** docs/api-contract.md "Bodies" already says decimal text is not canonical and clients compare by value (B3).
