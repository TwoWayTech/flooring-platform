# Session 2026-11-07: Phase 4, Tier 3 polish

## What was done
- Presenter guide: a floating panel (top bar toggle or the palette) listing the demo steps per product, each linking to its screen. The current step shows its talking point; steps the viewed role cannot open are greyed out. Open state is remembered per browser; toasts move aside while it is open.
- Loading, error and empty states: `QueryFallback` on every screen (skeleton while loading, the error with Try again when a read fails), a route error boundary, unhandled `ApiError`s from saves shown as toasts, and empty states for the installation week, meetings week, reports with no rows and aging with nothing owed.
- Simulated network in the guide footer (normal, slow, offline) to show those states live; it affects the next request, never saves offline, and resets on reload.
- Accessibility and reduced motion: axe-core on every screen in both themes (ADR 0003), skip link, focus returning to whatever opened a dialog or drawer, brand ink at 4.5:1 on its soft tint, tab contrast, accessible names that match visible text, tab panels, a `Segmented` toggle group, focusable scroll regions, and CSS animations that finish at once under reduced motion.
- Visual QA of every screen in light and dark at 1440 and 390 px. Fixed: a hydration mismatch in the theme toggle on server-rendered pages (admin), clipped job labels on the dashboard, a truncated persona name on the HR login, and a thin installation week (past jobs now fall in the two weeks before today).

## Decisions
- The network simulation wraps the ApiClient in a Proxy (`lib/api/network.ts`) instead of touching DemoStore, so a real client needs no change.
- The shell keeps its last good company data when a re-read fails (`keepDataOnError`); only the page shows the error.
- New `tests/e2e/console.spec.ts` loads every screen with a saved theme and fails on any console error or uncaught exception (spec section 6, "no console errors"). It catches the theme-toggle hydration bug when that fix is reverted.
- Shared screen list in `tests/e2e/screens.ts` feeds the phone layout, accessibility and console tests.
