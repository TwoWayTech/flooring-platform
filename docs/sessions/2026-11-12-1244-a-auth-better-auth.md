## Decisions and why
The owner decided four questions in plan mode. ADR 0029 has the full record.
1. **Cookie on the web host.** Next rewrites `/api/auth/*` and `/api-proxy/*` to apps/api, so the cookie is first-party on each product host (blueprint p17 rule 4).
2. **Per-company timeouts.** The API session check enforces `tenant_branding` idle and absolute timeouts (defaults 30 min and 12 h). Idle means no API request, to within 1 minute.
3. **Accounts.** Invite-only, with no public sign-up. The seed password comes from `SEED_USER_PASSWORD`.
4. **Company pick.** The host's subdomain company opens for its members. Otherwise the user's only company opens. Otherwise they get a chooser. Non-members, and users with no company, are refused.

Choices made while building:
- **CLI package.** `@better-auth/cli` is deprecated (last version 1.4), so the CLI is the `auth` package, 1.7.22.
  - `pnpm --filter @workspace/db auth:generate` regenerates the schema and keeps its header.
  - `generateId: "uuid"` gives uuid columns; the runtime makes UUID v7.
- **Migration 0001** was written by hand on top of drizzle-kit's output. drizzle-kit leaves out the `USING` casts and the foreign-key drop and re-add.
- **Dynamic base URL.** `AUTH_ALLOWED_HOSTS` and the dynamic base URL replace the planned `BETTER_AUTH_URL`, because Flooring and HR are different hosts.
- **No React client.** The web app uses four small `fetch` functions instead of Better Auth's React client, so it needs no new dependency.
- **No custom company endpoint.** The plugin's own `set-active` replaces the planned `POST /auth/active-company`.
  - Only `set-active` and `list` are open; every other organization endpoint answers 404 (CLAUDE.md rule 3).
  - Membership is checked before Better Auth runs. Better Auth's own refusal cleared the session's open company, which a test caught.
- **Email.** There is no no-op email adapter. The existing `memory` adapter is the local "no-op": it sends nothing and records messages, and the tests read them there.
- **Env files.** The API and db scripts now load the root `.env.local` as well as `.env`. The owner's file is `.env.local`, which nothing loaded before.
- **Session bridge.** In api mode `getSession()` maps the real session to the existing workspace session: company by slug, user by email to the seeded profile. Screens still read DemoStore until Settings → Users moves (P10).
- **Providers change.** `packages/providers` now exports `emailFor`; it already existed and was only exported, and nothing else in that package changed. CLAUDE.md asks first for providers changes, so this is flagged for review.
