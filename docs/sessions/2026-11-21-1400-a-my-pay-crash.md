# 2026-11-21 14:00, A: My pay crash (finding #26)

## Goal
Close click-through finding #26 (blocker): in api mode `/my/pay` crashed for every Employee and Manager with "[DecimalError] Invalid argument: undefined".

## Cause
`GET /me/portal` sends each pay line through the response interceptor, which strips the reserved pay-rate names (`baseRate`, `salaryAmount`, a week's `regularRate`; `SENSITIVE_FIELDS` in packages/shared) from anyone without `hr.employee.view_sensitive`. The Employee and Manager roles lack it. `my-pay.tsx` called `dec(line.salaryAmount)` to choose between Salary and Hours pay, so decimal.js threw on `undefined`. The web contract typed the line as a full `PayPeriodLine`, which hid the problem.

## What changed
- `apps/web/src/lib/api/contract.ts`: new `MyPayLine` type for the portal line, with the stripped fields optional.
- `apps/web/src/features/my/my-pay.tsx`: Salary or Hours pay comes from the person's own `payType` (or a salary the line does carry); a figure the answer left out shows as a dash labelled "Not shown". The server's stripping is unchanged.
- Tests: an API test (portal.int.test.ts) for an Employee (salaried) and a Manager (hourly) answer; a unit test (tests/unit/my-pay.test.tsx) rendering the page from a stripped answer; an api-mode Playwright test (tests/e2e-api/portal.spec.ts) opening `/my/pay` as Bri.
- docs/blueprint-delta.md row.
