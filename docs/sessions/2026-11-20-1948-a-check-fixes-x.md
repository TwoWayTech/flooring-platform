### Decisions
- **B1-1. The two shared reads are any-of.** The Users page reads `GET /roles` (role names beside people) and the Roles page reads `GET /users` (holder counts, which block deleting a held role). Gating each on its own page's switch would break the other page while it is on; gating on both keeps rule 13 (with both pages off, both routes are hidden). Their permission keys are unchanged.
- **B1-2. Support access sits under `settings.users`.** The panel is on Settings → Users, so all three routes, revoke included, answer 404 while the switch is off.
- **B1-3. Lock-out check for `settings.users` off.** What an Owner loses is exactly the Users page: inviting, changing roles, disabling, MFA resets, and approving or revoking support access. Nothing else reads these routes: the people directory every screen uses is `GET /company`, sign-in and step-up are session routes, and the Roles page keeps `GET /users` through B1-1. The one gap is revoking a support grant approved before the switch went off: that grant runs to its `expiresAt` (1 to 72 hours) and opens nothing yet (ADR 0054; docs/specs/platform-admin.md, owner question 2), and no new grant can be approved while the switch is off. Safest option taken: revoke stays behind the switch like the rest of the page (no hidden write reachable only by the API); owner question O1 if grants start opening the company.
