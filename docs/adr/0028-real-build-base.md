# 0028: Real-build base

Date: 2026-11-12. Status: accepted.

## Context
The demo is finished, tagged `demo-v3` and kept on branch `demo`. The real product starts on `main` with the blueprint's stack: NestJS API, Drizzle on plain PostgreSQL, provider adapters, one control database and one database per company. The blueprint leaves several choices open; this records them.

## Decisions

### Building the API
`packages/shared`, `packages/db` and `packages/providers` are consumed as TypeScript source, as the web app already does. NestJS needs decorator metadata, which esbuild alone cannot emit.

- apps/api is bundled with **tsup** (9.0.0). tsup uses SWC when the tsconfig emits decorator metadata.
- `@workspace/*` code is bundled in. Every npm package stays external.
- Under pnpm's strict layout the bundle can import only apps/api's own dependencies. So the runtime dependencies of the bundled workspace packages (`postgres`, `uuid`, `resend`, `@aws-sdk/*`) are also listed in apps/api/package.json, pinned to the same versions.
- Tests compile with **unplugin-swc**, for the same metadata, and use **supertest**.

Rejected options:
- A tsc build of every package: it needs a build step and `dist` in shared, which the web app does not want.
- Webpack: slow and heavy on a laptop.

### Libraries added
| Library | Why |
| --- | --- |
| NestJS 12 (`@nestjs/core`, `common`, `platform-express`, `config`, `swagger`, `testing`) | The blueprint's API framework. Version 12 is current; the blueprint pins none |
| drizzle-orm 0.45, drizzle-kit 0.31 | The blueprint's ORM and migrations |
| postgres (postgres.js) 4 | A standard TCP driver (blueprint "Provider portability", rule 2) |
| uuid 14 | UUID v7 ids made in the app, because PostgreSQL 16 has no `uuidv7()`. Seeds use UUID v5 so they are repeatable |
| @aws-sdk/client-s3, s3-request-presigner | One adapter for R2 and S3 |
| resend 6 | The blueprint's email provider |
| zod 4 | Environment and request validation, already used by web |
| tsup, @swc/core, unplugin-swc, supertest | Build and tests, above |

### Database
- **Column names.** Drizzle's `casing: "snake_case"` turns property names into column names, so the schema stays short.
- **Status fields.** Statuses are `text` columns typed with the unions from packages/shared. They are not PostgreSQL enums, because enums are painful to change in migrations; the API's Zod schemas validate the values.
- **Calendar days** are `date`. Moments are `timestamptz`.
- **Mapping from the demo.** Tables follow docs/data-model.md, with these choices:
  - Records nested inside another record become child tables where the blueprint names one, or where a rule needs rows: lines, rooms, attendees, coverages, checklist items, time entries, billing lines.
  - Snapshot-only objects stay `jsonb`: tax override, signature record, timesheet history, outbox attachments, import changes, pay weeks.
  - Every "by" field that held a name holds a user id.
  - Polymorphic links are a type column plus an id column.
  - Customer and supplier contacts are separate tables, not one `contacts` table.
  - `FileMeta` lists become `attachments` rows.
- **Tables left out**, because the demo dropped them:
  - `sales_orders`, `credit_notes`, `deposits`, `bill_lines`, `stock_levels`, `pto_balances`, `commission_rules`
  - price lists and customer groups
  - approvals and separation-of-duties tables, until P10 needs them
  - the ledger tables, until P12

  The Installation tables stay, because the demo kept their data.
- **Better Auth tables** were generated by `@better-auth/cli` 1.7.21 for email and password, twoFactor, passkey and organization, and are exempt from the table rules. P8 sets Better Auth to generate UUID user ids, so company tables can hold them in uuid columns.
- **Branding** sits in the control database (it is shown before sign-in). The other settings groups are one `jsonb` row per group in the company database. Tax rules and county rates are their own tables, because they have effective dates.
- **Connection strings** are encrypted with AES-256-GCM as `v1:` + base64(iv | tag | ciphertext). The prefix allows a later key rotation.
- **Migrations** run control first, then every company in creation order. The first failure stops the rollout, marks that company `failed` with the error, and leaves the rest on their version (blueprint p13).

### Web
`NEXT_PUBLIC_DATA_SOURCE=api` routes the ApiClient methods listed in `API_METHODS` to apps/api, and everything else to DemoStore. A module moves by adding its methods. In api mode the persona picker is replaced by a notice until P8, and `/api/demo/*` answers 404.

### CI
GitHub Free gives 2,000 minutes a month.

- **Branch pushes** run a fast job: lint, typecheck and unit tests.
- **Ready pull requests to main, and pushes to main**, run verify: Postgres, API tests, web build and Playwright smoke.
- **Ready pull requests** also run the full browser suite.

The estimate is in docs/real-build-plan.md.

## Consequences
- A new runtime dependency in a workspace package that the API uses must also be added to apps/api/package.json, or the built API fails to start. `pnpm --filter api build`, followed by starting it, catches this.
- `packages/db` paths to migrations assume the source layout. Migrations run from scripts, never from the bundled API.
