# 0029: Better Auth sign-in (P8 part 1)

Date: 2026-11-12. Status: accepted.

## Context
P8 part 1 (docs/real-build-plan.md, week 1) adds real sign-in: email and password with verification, session timeouts, the organization plugin with organization id = tenant id, and UUID user ids (ADR 0028). The blueprint leaves several choices open. The owner decided the four marked "(owner)" below on 2026-11-12. The rest follow from them or from the libraries.

## Decisions

### Libraries
| Library | Where | Why |
| --- | --- | --- |
| better-auth 1.7.22 | apps/api, packages/db | The blueprint's auth library. packages/db uses only `better-auth/crypto` to hash the seed password |
| auth 1.7.22 (dev) | packages/db | The Better Auth CLI. `@better-auth/cli` is deprecated and its last version is 1.4; the CLI now ships as `auth` |
| @better-auth/passkey 1.7.22 (dev) | packages/db | Only so the CLI keeps generating the passkey table for P8 part 2 |

The web app adds no auth library. Its four calls (sign in, choose company, session context, sign out) are small typed `fetch` functions in `apps/web/src/lib/session/api-auth.ts`. NestJS has no Better Auth wrapper here. The handler is mounted with `toNodeHandler` because our own guards arrive in P9.

### Schema
- `packages/db/src/control/auth.ts` is generated by `pnpm --filter @workspace/db auth:generate` from `packages/db/better-auth.config.ts`. That config is schema-only and lists the same plugins as the runtime: organization now, plus twoFactor and passkey for part 2.
- With `generateId: "uuid"` the CLI writes `uuid` ids and foreign keys. The runtime passes `generateId: () => uuidv7()`, so every new id is UUID v7. The column default `gen_random_uuid()` only applies if an id is ever omitted.
- `session.active_organization_id` stays `text`, as the CLI writes it.
- Migration `0001_auth_uuid_ids` changes the column types with explicit `USING id::uuid` casts. It drops and re-adds the foreign keys around the casts, and clears sessions and verification tokens, which are short-lived and could hold non-uuid ids. It also adds `organization.id → tenants.id`, `ON DELETE RESTRICT`.
- The table-rules test now also checks that the Better Auth tables have uuid ids.

### Accounts are invite-only (owner)
- Public sign-up is off (`disableSignUp`). Accounts come from provisioning and from admins' invitations; accepting an invitation is built with Settings → Users.
- `pnpm db:seed` gives every seeded Summit user a credential account with the password in `SEED_USER_PASSWORD` (at least 12 characters, never in code). Without the variable the users get no password.
- The minimum password length is 12 (blueprint p27).
- Sign-in on an unverified address is refused with `EMAIL_NOT_VERIFIED`, and a fresh verification link is sent through `EmailProvider`. The link points at the web host the request came from.

### The cookie lives on the web host (owner)
- In api mode Next.js rewrites `/api/auth/*` to apps/api's `/api/auth/*`, and `/api-proxy/*` to the rest of apps/api. The session cookie is therefore first-party on each product host: one cookie per domain, as blueprint p17 rule 4 asks. The web server and the proxy can see it.
- The cookie is httpOnly with SameSite=Lax, plus Secure and the `__Secure-` prefix in production.
- Better Auth uses a dynamic base URL. `AUTH_ALLOWED_HOSTS` lists the web hosts (wildcards allowed), and the host is read from `x-forwarded-host`, which the proxy sets (`trustedProxyHeaders`). A host not on the list is refused. This replaces the single `BETTER_AUTH_URL` from the plan, because Flooring and HR are different hosts.

### Per-company timeouts (owner)
- Better Auth's own expiry is a 7-day ceiling, and its refresh is off.
- `SessionService` checks each guarded request. When now − `created_at` exceeds the company's `absolute_timeout_min`, or now − `updated_at` exceeds its `idle_timeout_min`, the session row is deleted and the answer is 401 `session_expired`. The values are in `tenant_branding`, with defaults of 30 minutes and 12 hours (blueprint p28).
- A valid request moves `updated_at` forward at most once a minute, so "idle" means no API request and is accurate to one minute.
- Before a company is open, the defaults apply.
- The guard is opt-in for now; P9 makes guards global with the tenant guard.

### Which company opens (owner)
- A new session opens the company the host's subdomain names (`summit.flooringsuite.com`) if the user is a member, and refuses the sign-in (`not_a_member`) if not.
- Without a host company, a user with one company opens it. A user with several opens none until they choose: the login page shows a chooser, which calls the plugin's `set-active`. A user with no company is refused (`no_company`).
- The rule lives in `apps/api/src/core/auth/company-pick.ts`.
- Only the plugin's `set-active` and `list` endpoints are open. Every other organization endpoint answers 404, because membership, invitations and roles belong to our own modules behind the permission engine (CLAUDE.md rule 3).
- `set-active` is checked against membership before Better Auth runs. Better Auth's own refusal would also clear the open company.

### The web app in api mode
- `getSession()` reads `GET /auth/context` and bridges it to the existing workspace session. The company is matched by slug and the user by email to their seeded profile, because screens still read DemoStore until Settings → Users moves to the API (P10). An account without a profile sees "Your account is ready, but not this workspace".
- The login page keeps the demo's frame, now `LoginLayout`, shared by both modes.

## Left for later
- **P8 part 2:** TOTP with backup codes and passkeys; MFA required for Owner, Accountant, HR and platform admins (blueprint p27); rate limits and lockout, whose thresholds the blueprint does not give; `GET /public/branding?host=`, which brings the company's own logo and colour to the login page.
- **P9:**
  - Refusing a company that does not own the host's product (blueprint p17 rule 2), and a company that is not active.
  - Making the session guard global.
- Password reset and accepting invitations, which have screens but no spec yet.
- Mapping Better Auth `member.role` to the company's roles.

## Rejected
- **A shared parent cookie domain:** it needs real domains, which are not chosen, and does not work between localhost ports.
- **Global timeouts only:** the blueprint sets them per company.
- **Public sign-up during development:** it creates users without a company.
- **Better Auth's React client:** a dependency for four calls.
