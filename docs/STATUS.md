**How a stacked PR merges** (used for #46 to #54 and every later stacked PR; the merge-push guard allows only these forms):
1. `git fetch origin`, then check the branch out.
2. `git diff <head of the PR below> origin/main --stat` must print nothing (`gh pr view <n-1> --json headRefOid -q .headRefOid`).
3. `git merge -s ours origin/main`, never a rebase. Then `git diff HEAD^1 --stat` must print nothing. If either diff is not empty, do a real merge and get it reviewed.
4. `git push -q origin <branch>`, then `gh pr ready <n>`.
5. Check that a `pull_request` run really started. The `ready_for_review` run sometimes doesn't fire: `gh pr ready <n> --undo`, then `gh pr ready <n>`. A skipped draft `synchronize` run on the same commit shows "skipping" in `gh pr checks`; ignore it when the real run is green.
6. When `verify` and `e2e` are green, `gh pr merge <n> --squash --match-head-commit <sha>`.
7. No new review is needed while both diffs are empty: the code is what was reviewed.
8. Don't pass `--delete-branch` for a branch a worktree holds.
